# Теоретические вопросы к защите лабораторной работы №1

---

### Вопрос 1. Что такое класс, что такое объект, как создать объект класса?

* **Класс** — это абстрактный тип данных, пользовательский чертеж (шаблон/модель), описывающий структуру данных (состояние через поля) и поведение (методы), которыми будут обладать создаваемые на его основе сущности.
  * *Пример из работы:* Класс `Supplier` — это шаблон, определяющий, какими свойствами обладает любой поставщик в нашей системе.
* **Объект (экземпляр класса)** — это конкретная реализация класса в оперативной памяти компьютера, обладающая конкретными значениями полей (своим индивидуальным состоянием).
* **Создание объекта в Java:**
  Объект создается с помощью оператора `new` и вызова конструктора:
  ```java
  Supplier supplier = new Supplier(1, "ООО Авто-Лидер", ...);
  ```

### Вопрос 2. В чем заключается принцип инкапсуляции? Как получить доступ к полям объекта из внешнего класса?

* **Инкапсуляция** — это один из фундаментальных принципов ООП, заключающийся в:
  1. Объединении данных (полей) и методов работы с ними внутри одной сущности (класса).
  2. **Сокрытии внутренней реализации** от внешнего вмешательства (data hiding) с целью защиты данных от некорректных модификаций и сохранения инварианта объекта.
* **Реализация:** Все поля объявляются со спецификатором доступа `private` (или `protected` для классов-наследников). Прямой доступ к ним из внешних классов невозможен.
* **Получение доступа:** Доступ к полям предоставляется через открытые (публичные) интерфейсные методы:
  * **Геттеры (Getters)** — методы для чтения значений (например, `supplier.getName()`).
  * **Сеттеры (Setters)** — методы для контролируемого изменения значений, внутри которых выполняется валидация данных (например, `supplier.setName("Новое имя")`).

### Вопрос 3. Что такое конструктор, зачем он нужен, как описывается конструктор в произвольном классе?

* **Конструктор** — это специальный блок кода (метод инициализации), который автоматически вызывается средой выполнения при создании нового экземпляра класса через оператор `new`.
* **Зачем он нужен:** Гарантирует правильную инициализацию начального состояния объекта, выделение ресурсов и валидацию исходных параметров, делая невозможным создание объекта в некорректном (несогласованном) состоянии.
* **Описание в Java:**
  1. Имя конструктора обязано в точности совпадать с именем класса.
  2. У конструктора **нет** возвращаемого типа (даже `void`).
  3. Конструкторы могут быть перегружены (несколько конструкторов с разными сигнатурами параметров).
  ```java
  public Supplier(int id, String name, String inn, String phone) {
      // Инициализация полей
  }
  ```

### Вопрос 4. Опишите механизм создания объекта

Процесс создания объекта в Java при выполнении выражения `Supplier s = new Supplier(...)` состоит из следующих этапов:

1. **Загрузка класса (Class Loading):** Если класс `Supplier` еще не был загружен JVM, загрузчик классов (`ClassLoader`) загружает байт-код класса в память (Metaspace).
2. **Инициализация статической части:** Выполняются статические блоки инициализации и инициализируются статические переменные класса (один раз за время жизни программы).
3. **Выделение памяти в куче (Heap Allocation):** В куче (Heap) выделяется объем памяти, достаточный для размещения всех полей объекта (включая унаследованные от суперклассов) и заголовка объекта (Mark Word + Klass Word).
4. **Обнуление полей:** Всем полям объекта присваиваются значения по умолчанию (`0`, `0.0`, `false`, `null`).
5. **Вызов цепочки конструкторов:**
   * Сначала вызывается конструктор родительского класса (`super(...)`), поднимаясь по иерархии до `java.lang.Object`.
   * Выполняются нестатические блоки инициализации полей дочернего класса.
   * Выполняется тело самого вызванного конструктора.
6. **Возврат ссылки:** Оператор `new` возвращает ссылку (адрес в куче) на созданный экземпляр, которая записывается в ссылочную переменную `s` (находящуюся в стеке вызовов).

### Вопрос 5. Что такое метод класса (статический), в чем его отличие от метода объекта? Приведите два практических примера

* **Метод объекта (нестатический):** Привязан к конкретному экземпляру класса. Имеет неявный контекст `this` и оперирует состоянием конкретного объекта (его нестатическими полями). Вызывается через переменную объекта: `supplier.toShortString()`.
* **Метод класса (статический, `static`):** Принадлежит самому классу как типу данных, а не отдельным экземплярам. Для его вызова не требуется создавать объект. Внутри него нет указателя `this`. Вызывается через имя класса: `Supplier.validateInn("7701234567")`.

**Два практических примера необходимости статических методов:**
1. **Валидация данных до создания объекта:** Метод `Supplier.validateInn(inn)` позволяет проверить корректность значения до вызова конструктора или использования в других частях программы, не требуя создания заведомо некорректного объекта в памяти.
2. **Утилитные методы и фабрики:** Методы математических библиотек (например, `Math.sqrt()`) или утилитные методы работы со строками (`ValidationUtils.matchesRegex(...)`), которые не зависят от состояния какого-либо экземпляра и работают исключительно со своими аргументами.

### Вопрос 6. Опишите структуру классов Вашего языка, как в нее вписывается написанный Вами класс?

* В языке **Java** существует строгая древовидная иерархия классов с **одиночным наследованием**.
* Абсолютным корнем всей иерархии является класс **`java.lang.Object`**. Любой класс в Java, если явно не указан предок, неявно наследуется от `Object`.
* **Встраивание написанных классов в иерархию:**
  ```
  java.lang.Object
         ▲
         │ (extends)
  models.SupplierShort
         ▲
         │ (extends)
  models.Supplier
  ```
  * `SupplierShort` явно не указывает предка, поэтому его прямым родителем является `java.lang.Object`.
  * `Supplier` явно наследуется от `SupplierShort` (`class Supplier extends SupplierShort`).
  * Таким образом, `Supplier` наследует функционал как `SupplierShort`, так и базового класса `Object`.

### Вопрос 7. Опишите принцип наследования, переопределение методов и способы вызова переопределенного метода

* **Наследование** — механизм ООП, позволяющий создать новый класс на основе уже существующего, перенимая его поля и методы и добавляя новую функциональность либо изменяя существующую. Реализует отношение «is-a» («является»).
* **Переопределение метода (Method Overriding):**
  * Это изменение реализации метода базового класса в классе-наследнике с сохранением точной сигнатуры (имени, параметров и возвращаемого типа).
  * В Java помечается аннотацией `@Override`.
  * *Пример:* Класс `Supplier` переопределяет метод `toString()`, унаследованный от `SupplierShort` / `Object`, чтобы вывести расширенный список полей (ОГРН, адрес, email).
* **Способы вызова переопределенного метода:**
  * Изнутри класса-наследника вызвать оригинальный метод базового класса можно с помощью ключевого слова **`super`**:
    ```java
    public String toShortString() {
        return super.toString(); // вызов метода toString() из SupplierShort
    }
    ```

### Вопрос 8. Опишите принципы работы конструкторов для наследуемых классов

1. **Обязательный вызов родительского конструктора:** Конструктор класса-наследника **всегда обязан** вызвать один из конструкторов родительского класса.
2. **Ключевое слово `super(...)`:** Вызов конструктора родителя осуществляется явным вызовом `super(аргументы...)`.
3. **Первая строка:** Вызов `super(...)` (или вызов другого конструктора этого же класса `this(...)`) обязан быть **самой первой исполняемой строкой** в конструкторе наследника.
4. **Конструктор по умолчанию:** Если в конструкторе наследника нет явного вызова `super(...)`, компилятор Java автоматически вставляет вызов конструктора родителя без параметров: `super();`. Если у родителя нет конструктора без параметров, возникнет ошибка компиляции.
5. **Порядок выполнения:** Сначала полностью отрабатывает конструктор родительского класса (инициализируя поля предка), и только после этого управление передается в конструктор дочернего класса.

### Вопрос 9. Какие методы объекта обязательно есть у любого написанного Вами класса, опишите, что они делают

Поскольку любой класс в Java наследуется от `java.lang.Object`, каждый объект автоматически обладает следующими фундаментальными методами:

1. **`boolean equals(Object obj)`** — проверяет логическое равенство двух объектов. По умолчанию в `Object` сравнивает ссылки (`==`), поэтому в классах сущностей его переопределяют для сравнения по ключевым полям (`id`, `inn`).
2. **`int hashCode()`** — возвращает числовой хэш-код объекта. Используется хэш-коллекциями (`HashMap`, `HashSet`). Обязан соблюдать контракт с `equals`: у равных по `equals` объектов хэш-коды должны быть одинаковыми.
3. **`String toString()`** — возвращает строковое представление объекта. По умолчанию возвращает `ИмяКласса@хэшКод`. Переопределяется для удобного вывода информации об объекте в консоль или лог.
4. **`Class<?> getClass()`** — возвращает объект `Class`, содержащий метаинформацию о типе данного объекта во время выполнения программы (используется для рефлексии).
5. **`protected Object clone()`** — создает и возвращает поверхностную копию объекта (требует реализации интерфейса `Cloneable`).
6. **`wait()`, `notify()`, `notifyAll()`** — группа методов низкоуровневой синхронизации потоков (многопоточности) на встроенном мониторе объекта.
7. **`protected void finalize()`** *(deprecated в современных версиях Java)* — вызывался сборщиком мусора перед уничтожением объекта в памяти.
