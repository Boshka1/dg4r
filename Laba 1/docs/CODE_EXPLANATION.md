# Построчный разбор кода Лабораторной работы №1

Этот документ написан простым и понятным языком специально для защиты. Если преподаватель покажет на любую строчку кода и спросит: *«А что это такое?»* — здесь есть готовый ответ.

## 1. Файл `ValidationUtils.java` (Утилитный класс валидации)

### Зачем нужен этот класс? (Пункт 5 ТЗ)
Чтобы не писать в каждом методе одни и те же проверки: `if (str == null || str.trim().isEmpty())` и `Pattern.matches(...)`. Вся повторяющаяся логика собрана здесь один раз.

### Построчные пояснения:
* `package utils;` — сообщает Java, что этот файл относится к пакету (папке) `utils`.
* `import java.util.regex.Pattern;` — подключает встроенный в Java класс для работы с регулярными выражениями (шаблонами проверки строк).
* `public final class ValidationUtils` — 
  * `public` — класс виден отовсюду.
  * `final` — от этого класса **запрещено наследоваться** (стандарт для утилитных классов).
* `private ValidationUtils() {}` — **приватный конструктор**. Запрещает писать `new ValidationUtils()`. Утилитный класс содержит только статические методы и не должен создавать объекты в памяти.
* `public static boolean isBlank(String value)`:
  * `static` — метод класса (вызывается без создания объекта: `ValidationUtils.isBlank(...)`).
  * `boolean` — возвращает либо `true` (пусто), либо `false` (не пусто).
  * `value.trim().isEmpty()` — `.trim()` убирает пробелы по краям строки, а `.isEmpty()` проверяет, остался ли хоть один символ.
* `public static boolean matchesRegex(String value, String regex)`:
  * Принимает значение `value` (например, телефон) и шаблон `regex`.
  * Вызывает `Pattern.matches(regex, value.trim())`, проверяя, соответствует ли строка заданному формату.
* `public static boolean checkLength(String value, int min, int max)`:
  * Проверяет, укладывается ли длина строки в диапазон от `min` до `max` символов.

## 2. Файл `SupplierShort.java` (Базовый класс краткой версии)

### Зачем нужен этот класс? (Пункты 8 и 9 ТЗ)
Это **базовый класс** (родитель). Он хранит минимальный набор полей, достаточный для идентификации поставщика: `id`, `name`, `inn`, `phone`.

### Построчные пояснения:
* `public class SupplierShort` — объявление открытого класса.
* `protected int id;`
  `protected String name;`
  `protected String inn;`
  `protected String phone;`
  * Модификатор `protected` означает: **снаружи класса поля недоступны (инкапсуляция)**, но классы-наследники (наш `Supplier`) имеют к ним прямой доступ.
* `private static final String INN_REGEX = "^\\d{10}$|^\\d{12}$";`:
  * `private` — шаблон виден только внутри этого класса.
  * `static final` — константа, создается в единственном экземпляре для всех объектов.
  * `^\\d{10}$` означает: ровно 10 цифр (ИНН юрлица) или ровно 12 цифр (ИНН ИП).
* `public SupplierShort(int id, String name, String inn, String phone)` — **основной конструктор**:
  * Внутри вызывает `setId(id)`, `setName(name)` и т.д.
  * **Зачем вызывать сеттеры в конструкторе?** Чтобы сразу сработала валидация! Нельзя создать объект с неверными данными.
* `public SupplierShort(SupplierShort other)` — **копирующий конструктор**:
  * Принимает другой объект `SupplierShort` (или его потомка `Supplier` благодаря полиморфизму!) и копирует из него данные.
* `public SupplierShort(String shortCsv)` — **конструктор из строки**:
  * Принимает строку вида `"1;ООО Авто;7701234567;+79991234567"`.
  * `shortCsv.split(";")` разрезает строку на массив частей по символу `;`.
  * `Integer.parseInt(...)` переводит строку с цифрами в целое число `int`.
* **Геттеры и сеттеры:**
  * `public int getId() { return id; }` — безопасно отдает значение приватного поля.
  * `public void setId(int id) { if (!validateId(id)) throw new IllegalArgumentException(...); this.id = id; }` — проверяет значение перед записью. Если валидация не прошла, программа выбрасывает ошибку `IllegalArgumentException` и прерывает работу.
  * `this.id = id` — `this.id` означает поле текущего объекта, а просто `id` — аргумент метода.
* `@Override public String toString()` — переопределяет стандартный метод Java для вывода объекта в виде текста: `SupplierShort [#1]: Название | ИНН | Тел`.
* `@Override public boolean equals(Object o)`:
  * Проверяет, равны ли два поставщика.
  * Если `id` и `inn` совпадают — объекты считаются одинаковыми.
* `@Override public int hashCode()`:
  * Возвращает уникальное число (хэш) объекта. В Java есть строгое правило: если `equals` вернул `true`, то `hashCode` у этих двух объектов **обязан быть одинаковым**!

## 3. Файл `Supplier.java` (Полный класс-наследник)

### Зачем нужен этот класс? (Пункты 3, 6, 7, 9 ТЗ)
Это расширенная версия поставщика со всеми реквизитами: ОГРН, email, адрес, контактное лицо.

### Построчные пояснения:
* `public class Supplier extends SupplierShort`:
  * **Ключевое слово `extends` — это наследование!**
  * `Supplier` является наследником (потомком) `SupplierShort`.
  * Ему **не нужно** заново объявлять поля `id`, `name`, `inn`, `phone` и их геттеры/сеттеры — он автоматически получил их от родителя!
* `private String ogrn;`
  `private String email;`
  `private String address;`
  `private String contactPerson;`
  * Объявляются только **новые специфичные поля**, которых не было в родителе. Модификатор `private` обеспечивает строгую инкапсуляцию.
* `public Supplier(int id, ..., String contactPerson)` — полный конструктор:
  * `super(id, name, inn, phone);` — **САМАЯ ВАЖНАЯ СТРОЧКА!** 
  * Ключевое слово `super(...)` вызывает конструктор родительского класса (`SupplierShort`). 
  * По правилам Java вызов `super(...)` обязан стоять **самой первой строкой** в конструкторе потомка.
  * После этого вызываются сеттеры дополнительных полей: `setOgrn(ogrn)`, `setEmail(email)` и т.д.
* `public Supplier(String data)` — перегруженный «умный» конструктор:
  * Если строка начинается на `{` — вызывает разбор JSON `initFromJson(...)`.
  * Иначе вызывает разбор CSV `initFromCsv(...)`.
* `public String toShortString() { return super.toString(); }`:
  * Вызывает метод `toString()` родителя, получая краткую версию.
* `@Override public String toString()`:
  * Формирует подробную многострочную карточку со всеми 8 полями.
* `@Override public boolean equals(Object o)`:
  * `if (!super.equals(o)) return false;` — сначала спрашивает у родителя, совпадают ли базовые поля (`id` и `inn`).
  * Если да, дополнительно сверяет поле `ogrn`.

## 4. Файл `Main.java` (Демонстрационная программа)

* `public static void main(String[] args)` — главная точка входа, с которой начинается исполнение Java-программы.
* `fullSupplier instanceof SupplierShort` — оператор `instanceof` возвращает `true`, доказывая компилятору и преподавателю, что объект `Supplier` действительно является экземпляром суперкласса `SupplierShort` (полиморфизм).
* Блок `try { ... } catch (IllegalArgumentException e) { ... }`:
  * В блоке `try` мы намеренно пытаемся создать поставщика с неверным ИНН `"12345"`.
  * Конструктор выбрасывает исключение, и управление переходит в блок `catch`.
  * Это доказывает выполнение требования ТЗ: **«Сделать так, чтобы существование объекта с неразрешёнными полями было невозможно»**.
